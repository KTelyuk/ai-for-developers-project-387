# Тикеты в GitHub Issues, спецификация в репозитории

Status: accepted

Сначала тикеты и карта wayfinder лежали markdown-файлами в `docs/`. Работу будет проверять сотрудник компании, и смотреть он будет на GitHub, поэтому тикеты перенесены в GitHub Issues: метки показывают статус (`ready-for-agent`, `ready-for-human`, `wayfinder:*`), блокировки — родные зависимости issues, карта — issue с sub-issues, а коммит с `(#N)` в заголовке и `Closes #N` в PR связывает код с задачей и закрывает её. Спецификация осталась в `docs/spec.md`: её правки проходят ревью вместе с кодом.

## Consequences

- Номера issues и PR общие, поэтому номер тикета не совпадает с порядком нарезки; в тексте на тикеты ссылаются по номеру issue или по названию.
- Агенту для работы с тикетами нужен `gh` с доступом к сети; правила — в `docs/agents/issue-tracker.md`.
