# Главная без списка типов встреч

Status: accepted

Первоначальный план README клал на главную список типов встреч с кнопками «Записаться». Мы решили иначе: главная только рассказывает о сервисе и ведёт одной кнопкой «Записаться» на страницу бронирования (`/book`), а тип встречи гость выбирает первым шагом бронирования. Так главная не зависит от API и могла выйти первой фичей, ещё до эндпоинта `GET /api/event-types`, а весь выбор — тип, день, время — живёт в одном месте.

## Considered Options

- **Список типов на главной (план README).** Гость выбирает тип в один клик с главной, но главная ждёт API типов встреч, а выбор типа оказывается на другой странице, чем выбор дня и времени.
- **Описание и одна кнопка (выбрано).**

## Consequences

- Тикет «Бронирование: выбор времени» начинается с выбора типа встречи из списка.
- Не добавляйте на главную запросы к API, не пересмотрев это решение: тест главной проверяет, что она не обращается к SDK.
