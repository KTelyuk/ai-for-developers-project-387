# Тесты фронтенда входят в общий прогон

Status: accepted

Компоненты фронтенда тестируются на Vitest + Testing Library в jsdom, и эти тесты входят в `mise run test` наравне с тестами бэкенда — а значит, в `mise run check`, pre-push хук и CI. Мы выбрали Vitest, потому что он уже стоит в бэкенде и работает поверх конфигурации Vite (алиас `@/`, плагины); jsdom — потому что тесты компонентов должны быть быстрыми и не требовать браузера, а адаптивность и реальную навигацию проверят e2e-тесты Playwright.

## Considered Options

- **Отдельная задача для тестов фронтенда вне `check`.** Быстрее pre-push, но ломающийся фронтенд проходит CI незамеченным.
- **Только e2e на Playwright.** Ближе к реальности, но медленно и требует запущенного приложения на каждом прогоне.

## Consequences

- Упавший тест фронтенда блокирует пуш и CI так же, как тест бэкенда.
- HTTP в тестах подменяется через MSW (`frontend/src/test/msw.ts`): запрос без обработчика завершается ошибкой и не уходит в сеть. SDK в тестах ходит на origin jsdom, потому что `fetch` в Node не принимает относительный адрес. «Страница не делает запросов» проверяется списком запросов, которые увидел MSW.
